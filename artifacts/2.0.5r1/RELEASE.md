# DanmuPlus 2.0.5r1 发布说明

2.0.5r1 面向 Synology 套件版 Emby 4.9.5.0，重点完善智能匹配的站点故障
隔离、手动关键词、季度评分、稀疏集号映射与旧预览写入安全。

从最新正式 2.0.3r10 升级时，同时包含 2.0.4r2 中仍保留的 TMDB 别名、
库内信息和七日重放能力。

## 主要变化

- 单个弹幕站点失败时，其他已完成站点仍可继续评分和匹配；全部站点失败、
  明确取消、候选歧义或权威映射不完整仍会安全停止。
- 手动关键词显示服务端给出的普通分数、原因与按站点公平的 60 条结果窗，
  但不会自动选择、下载、绑定或写入元数据。
- TMDB 别名临时失败后继续尝试后续别名；全部别名未达到当前接受阈值时，
  隐藏内部别名候选并允许使用权威父剧名重新匹配。
- 季度评分最终采用父剧名 60、季名 20、精确年份 20、集数 0。集数差异只在
  权威映射后以黄色提示显示，不影响评分或下载资格。
- 对符号型季度标题增加严格完整标题兜底：只有同一标题对的宽松季名残余
  同时为空时，才用 NFKC 后的完整标题符号等价补足季名分。
- 临时复合映射失败会显示明确原因；整剧预览偶发返回空 Season 时只自动
  重试一次。
- 复合季度映射说明每个适用结果只显示一次；配置页显示 `DanmuPlus 配置`，
  源码链接指向本项目 `main` 分支。

## 稀疏集号映射（V22/V28）

- 来源的显式 Episode number 与稳定显示顺序分开保存，不再把列表位置伪装成
  来源集号。
- 默认首段在双方编号可靠时采用零偏移。库内缺少 E7-E9 时，现有 E10 仍映射
  来源 E10，而不是压缩到来源 E7。
- 用户确认的显式锚点按编号差继续：E29→来源 E1 时，即使本地缺 E30，
  E31 仍映射来源 E3。
- 任何一侧编号不可靠时，整个窗口使用稳定位置兜底；同一窗口不混用编号与
  位置模式。精确来源 EpisodeId 是权威来源锚点。
- V22 计划指纹覆盖对齐意图、锚点、窗口、来源顺序与精确映射；过期预览会在
  下载、标识符或元数据写入前被拒绝。
- 显式单季仍可处理 Season 0；整剧与无人值守/媒体导入路径在搜索前跳过
  Season 0。逐集重试和七日重放继续使用冻结的本地集、来源集与 CommentId。
